# Migrating from version 6 to version 7

Version 7 is a major release because the React Native peer floor moves to
0.75.0. The component API and chart configuration shape are unchanged.

## 1. Upgrade React Native and React

Choose a supported React Native release from 0.75 through 0.87 and use the
React version required by that release. The wrapper peers are:

```json
{
  "react": "^18.0.0 || ^19.0.0",
  "react-native": ">=0.75.0 <0.88.0"
}
```

Applications that must remain on React Native 0.74 or earlier should remain on
the version 6 wrapper line.

If you are also moving to **React Native 0.87**, note that it removes the
`backgroundColor` prop from `StatusBar`. Applications that set it fail to
type-check with
`Property 'backgroundColor' does not exist`. Remove the prop; this is a React
Native change and no wrapper API is affected.

## 2. Install the native dependency set

Declare the native packages directly in the application. Direct declarations
make React Native CLI and Expo autolinking deterministic, including with
package managers and local package archives that do not hoist dependencies in
the same way.

```bash
npm install react-native-fusioncharts@7.0.0-rc.0 \
  @dr.pogodin/react-native-fs@2.40.0 \
  @notifee/react-native@^9.1.8 \
  @react-native-camera-roll/camera-roll@^7.10.2 \
  react-native-share@^12.3.1 \
  react-native-webview@^14.0.1
```

If the application directly installed the unmaintained `react-native-fs`
package for the wrapper, remove that declaration. Version 7 uses the compatible
`@dr.pogodin/react-native-fs` fork with New Architecture support.

The filesystem fork is a native peer and must match the React Native minor.
The command above is for RN 0.87; use the version in the
[compatibility table](../compatibility.md#react-native-matrix) for other RN
minors. This prevents older RN codegen from receiving a newer, incompatible
native-module spec while allowing current RN releases to use current native
APIs.

When upgrading an RN 0.75 application with npm, add `--legacy-peer-deps` to
the install command. Filesystem 2.28.1 otherwise causes npm to install its
unused `react-native-windows` peer into an iOS/Android-only project.

Set the Android application `minSdkVersion` to at least 24. This is required by
`react-native-webview@14`; the RN 0.75 template defaults to 23.

For iOS, run `pod install` after changing JavaScript dependencies. Confirm the
photo-library usage descriptions and the legacy Android write permission in the main
[installation guide](../../README.md#overview).

## 3. Expo applications

Use an Expo development client and native prebuild; Expo Go cannot load this
wrapper's native dependencies.

```bash
npx expo install expo-dev-client expo-build-properties
npx expo prebuild --clean
npx expo run:android
# or: npx expo run:ios
npx expo start --dev-client
```

Add the Notifee local Maven repository through `expo-build-properties` as shown
in the [Expo installation guide](../../README.md#developing-applications-with-fusioncharts-and-expo).
Do not add `@notifee/react-native` 9.1.8 to the Expo `plugins` array; its native
projects are handled by autolinking.

One Expo detail is worth knowing before you start: Expo SDK 54 pins React
Native 0.81.5 with React 19.1.0. Keep those versions rather than forcing React
Native 0.81.6, which requires a newer React. See "Known upstream issues" in the
[compatibility guide](../compatibility.md).

## 4. Export and offline assets

Client export now captures FusionCharts browser downloads inside the WebView
and passes them to the native filesystem/share path. JPEG, PNG, SVG, PDF, CSV,
and XLSX exports remain enabled through the existing `exportEnabled` chart
configuration. No export server is required.

FusionCharts theme fonts are embedded in the generated WebView assets. Chart
rendering no longer fetches theme fonts from Google Fonts.

Use a definite numeric chart height when the component is inside a
`ScrollView`; a percentage height can resolve to zero when the parent has no
bounded height.

## 5. Validate the application

After the native rebuild, verify chart render, data updates, event callbacks,
and each export format used by the application. Expo applications must perform
this pass in a development build or release build, not Expo Go.
